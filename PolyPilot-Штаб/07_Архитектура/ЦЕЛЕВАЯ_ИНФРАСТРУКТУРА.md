# Целевая инфраструктура PolyPilot

> [[ДОРОЖНАЯ_КАРТА_ОНЛАЙН]] · [[ДОМ_ШТАБ]]

> **Принцип:** GitHub — центр (код + CI). Frontend и backend — **раздельно**.

---

## Схема

```text
                    ┌─────────────────┐
                    │     GitHub      │
                    │  polypilot-     │
                    │   platform      │
                    └────────┬────────┘
              push           │           push
         ┌───────────────────┼───────────────────┐
         ▼                   │                   ▼
  ┌──────────────┐           │            ┌──────────────┐
  │   Vercel     │           │            │   Railway    │
  │  platform/   │           │            │   backend/   │
  └──────┬───────┘           │            └──────┬───────┘
         │                   │                   │
         ▼                   │                   ▼
  polypilot.pro              │            api.polypilot.pro
  (лента, маркетинг)         │            (API, harvest, LLM)
```

| Слой | Где | Папка | URL (цель) |
|------|-----|-------|------------|
| **Сайт** | Vercel (или Netlify) | `platform/` | `https://polypilot.pro` |
| **API + агенты** | Railway → позже VPS | `backend/` | `https://api.polypilot.pro` |
| **Код** | GitHub | весь mono-repo | github.com/AndreySavinWB/polypilot-platform |
| **Запасной фронт** | GitHub Pages | `platform/` | `*.github.io/polypilot-platform/` |

## 1. Домен

Рекомендация: **`polypilot.pro`** (или `.ru`, если аудитория только RU).

| Запись | Назначение |
|--------|------------|
| `@` / `www` | Vercel (сайт) |
| `api` | Railway (backend) |

---

## 2. Frontend — Vercel

### Подключение (один раз)

1. [vercel.com](https://vercel.com) → **Add New Project** → Import `polypilot-platform`
2. **Root Directory:** `platform` *(или оставить корень — в репо есть `vercel.json` с `outputDirectory`)*
3. Framework Preset: **Other** (статика, без сборки)
4. Deploy

### Домен

Project → **Settings → Domains** → `polypilot.pro` → DNS по инструкции Vercel.

### Автодеплой

Каждый `git push` в `main` с изменениями в `platform/` → новая версия сайта (~1 мин).

### Файлы в репо

- `vercel.json` (корень) — `outputDirectory: platform`
- `netlify.toml` — альтернатива Netlify

---

## 3. Backend — Railway

### Подключение (один раз)

1. [railway.app](https://railway.app) → **New Project** → **Deploy from GitHub**
2. Репозиторий: `polypilot-platform`
3. **Root Directory:** `backend`
4. Variables (из `.env.example`):

| Variable | Пример |
|----------|--------|
| `POLZA_API_KEY` | `pza_...` |
| `LLM_PROVIDER` | `polza` |
| `PP_SCAN_LIMIT` | `300` |
| `PP_TOP_N` | `10` |

5. **Settings → Networking → Generate Domain** → `*.up.railway.app`
6. Проверка: `GET https://…/health`

### Cron (harvest)

Railway → Service → **Cron** (или отдельный Cron service):

```bash
python scripts/harvest_test_events.py
```

Расписание: `0 */6 * * *` (каждые 6 ч).

Harvest пишет:

- `backend/data/events-live.json` → отдаётся как `GET /api/live/events`
- `platform/data/events-live.js` → только если в деплое есть папка `platform` (на Railway обычно нет — ок)

### Файлы в репо

- `backend/railway.toml`
- `backend/Procfile`
- `backend/runtime.txt`

---

## 4. Связка сайт ↔ API

### Сейчас (этап 2)

Статика: `platform/data/events-live.js`  
Обновление: GitHub Actions **Harvest live events** → commit → Vercel/Pages пересобирают сайт.

### Цель (этап 3+)

1. Backend на Railway отдаёт `GET /api/live/events`
2. В `platform/assets/js/pp-config.js`:

```javascript
window.PP_CONFIG = {
  apiBase: "https://api.polypilot.pro",
  useLiveApi: true,
};
```

3. Сайт подгружает live-блок с API (без commit JSON в git).

## 5. GitHub Actions (переходный слой)

| Workflow | Назначение | Когда отключать |
|----------|------------|-----------------|
| `pages.yml` | Запасной фронт на GitHub Pages | После Vercel + домен |
| `harvest.yml` | Harvest → commit `events-live.js` | После cron на Railway |
