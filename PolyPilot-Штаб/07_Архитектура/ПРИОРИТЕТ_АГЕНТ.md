# Priority Agent — рубрика отбора событий

> **🔒 ЗАФИКСИРОВАНО:** `rubric_v1` · 8 июня 2026 · см. [[СТАТУС_ЛАБОРАТОРИИ]]

Жёсткий, воспроизводимый чек-лист. Цель: из всего Polymarket взять события, которые **быстрее всего ведут к деньгам** — с понятным прогнозом и контролируемым риском. Мусор отсекается до анализа.

---

## Цикл работы

```text
1. Market Scanner — сканирует до 300 активных событий Polymarket (пагинация API)
2. Hard Gates — жёсткий отсев мусора (без LLM)
3. Rubric v1 — числовой score 0–100 по весам
4. LLM boost — уточнение топ-20 по новостному драйверу и резолву
5. Top-N — только лучшие идут в News Scout → Risk → Verdict
```

Код: `PolyPilot-Backend/src/agents/priority.py`

---

## Hard Gates (отсев мусора)

Событие **сразу rejected**, если:

| # | Условие | Зачем |
|---|---------|-------|
| 1 | Ликвидность < $5 000 | Нельзя нормально войти/выйти |
| 2 | Общий объём < $25 000 | Рынок неживой |
| 3 | Объём 24ч < $500 | Нет текущего интереса |
| 4 | Описание < 80 символов | Непонятный резолв |
| 5 | Нет даты окончания | Нельзя оценить горизонт |
| 6 | Горизонт < 1 дня | Просрочено / закрывается |
| 7 | Горизонт > 540 дней | Слишком долго до денег |
| 8 | Цена ≤ 2% или ≥ 98% | Рынок уже «решён», edge мёртв |

## Рубрика (100 баллов)

| Критерий | Вес | Что измеряет | Источник |
|----------|-----|--------------|----------|
| **Объём торгов** | 25% | Деньги в рынке + активность 24ч | API: volume, volume24hr |
| **Ликвидность** | 20% | Качество исполнения | API: liquidity |
| **Новостной драйвер** | 25% | Будет ли цена двигаться от новостей | Эвристика + LLM (топ-20) |
| **Понятность резолва** | 15% | Можно ли чётко понять «Да/Нет» | Эвристика + LLM (топ-20) |
| **Скорость к деньгам** | 10% | Короткий горизонт = быстрее результат | API: endDate |
| **Качество цены** | 5% | Есть ли неопределённость (edge жив) | API: outcomePrices |

### Скорость к деньгам (горизонт)

| Дней до резолва | Балл |
|-----------------|------|
| ≤ 14 | 95 |
| ≤ 45 | 85 |
| ≤ 90 | 75 |
| ≤ 180 | 55 |
| ≤ 365 | 35 |
| > 365 | 15 |

### Решения по итоговому score

| Score | Решение | Действие PP |
|-------|---------|-------------|
| ≥ 70 | **accepted** | Полный анализ + «горячее» на сайте |
| 55–69 | **watchlist** | В ленте, без приоритета |
| < 55 | **rejected** | Не показываем, мусор |

## Чек-лист Priority Agent (для продукта)

### Блок A — можно ли торговать

- [ ] Ликвидность ≥ $5K
- [ ] Объём 24ч ≥ $500
- [ ] Общий объём ≥ $25K
- [ ] Цена не у 0% / 100%

### Блок B — быстро ли к деньгам

- [ ] Горизонт 14–180 дней (идеал)
- [ ] Есть конкретный дедлайн резолва
- [ ] Рынок активен прямо сейчас (volume24hr)

### Блок C — понятен ли прогноз

- [ ] Описание объясняет, что = «Да»
- [ ] Есть официальный источник резолва
- [ ] Не больше 4 подрынков без явного лидера

### Блок D — есть ли драйвер

- [ ] Тема в новостях (политика, макро, крипто, геополитика)
- [ ] Ближайший катализатор (заседание, выборы, отчёт, дедлайн)
- [ ] Объём 24ч растёт относительно общего

### Блок E — итог

- [ ] Score ≥ 70 → **в топ PP**
- [ ] Score 55–69 → наблюдение
- [ ] Иначе → **отклонить**

## Промпт LLM (только топ-кандидаты)

LLM **не решает всё сам** — он уточняет 2 критерия:

- `newsDriverScore` 0–100
- `resolutionClarityScore` 0–100
- `reason` — 1–2 предложения на русском

Финальный балл: 70% LLM + 30% эвристика (для стабильности).

## API и запуск

```powershell
# Полный цикл: скан 300 → топ-10 → анализ → сайт
cd PolyPilot-Backend
.\.runtime\python.exe scripts\harvest_test_events.py

# Только скан без LLM-анализа (через server)
GET /api/priority/scan?scan=300&top=20
```

Переменные окружения:

- `PP_SCAN_LIMIT=300` — сколько событий сканировать
- `PP_TOP_N=10` — сколько лучших анализировать полностью

## Принцип «без мусора»

```text
300 событий Polymarket
    → ~40–80 проходят Hard Gates
    → ~10–25 получают accepted
    → топ-10 идут на сайт с полным War Room
```

Пользователь видит не «что попало в API», а **отфильтрованный шорт-лист прибыльных рынков**.
